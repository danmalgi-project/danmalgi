# wf-review — 4단계 실행 절차

`reviewer` 에이전트의 실행 지침. 목표: 변경이 계획을 충족하고 경계면·표준을 지키는지 독립 검수. **진단만 하고 고치지 않는다.**

## 절차

1. **입력 확인** — `01_brainstorm.md`, `02_plan.md`, `03_work.md`와 실제 `git diff`를 읽는다.
2. **계획 준수 검증** — 계획의 각 작업이 완료 조건대로 반영됐는지 대조한다.
3. **경계면 교차 비교** (핵심) — 존재 확인이 아니라 shape 일치를 본다:
   - gRPC 핸들러 반환/요청 ↔ `proto/**`의 메시지 정의 ↔ `signaling_mapper.go` ↔ usecase 시그니처를 **동시에 읽어** 필드가 일치하는지.
   - 새 fx provider가 소비처 `module.go`에 실제 배선됐는지.
4. **표준/안전성** — 계층 경계, 에러 처리(`pkg/errors`)·로깅 패턴, 세션/트랙 상태의 동시성 안전성.
5. **실행 검증** — 아래 명령을 직접 돌려 근거로 삼는다.
6. **판정 & 출력** — PASS 또는 재작업 필요를 명시한 `04_review.md` 작성.

## 실행 명령

```sh
go build ./...
go test ./...
go vet ./...
git diff        # 실제 변경 확인
```

## 산출물 형식 (`04_review.md`)

```markdown
# 4단계: 리뷰 — <제목>

## 판정            (PASS / 재작업 필요)
## 계획 준수        (작업별 반영 여부)
## 발견사항        (각 항목: 심각도[blocking/제안] · 위치[파일:라인] · 문제 · 근거 · 권장 조치)
## 실행 검증        (돌린 명령 + 결과)
## 재작업 항목      (worker에 넘길 blocking 목록; 없으면 "없음 → PASS")
```

## 원칙

- 존재 확인이 아니라 **경계면 교차 비교**가 핵심이다.
- 빌드·테스트를 직접 실행해 근거로 삼는다. `-race`는 **Windows에서만** PowerShell 툴로 실행하고(Bash sandbox가 cgo를 차단 — CLAUDE.md 참고), Linux/macOS에서는 Bash로 그대로 실행한다. IDE 진단(gopls)이 실제 빌드와 어긋나면(예: TDD로 나중에 추가된 심볼의 stale `undefined`, 파일 개명·이동 직후의 없는 경로 기준 오류나 "미사용 함수" 오탐) IDE가 아니라 실제 `go build`/`go test` 결과를 신뢰하며, stale 진단을 blocking으로 오판하지 않는다.
- **테스트 통과를 커버리지로 착각하지 않는다 — 자문에 그치지 말고 실제로 변형해 돌린다.** 계획서에 커버리지 자기검증 항목이 있으면 각 항목을 **임시 mutation으로 실행**해 "실패해야 하는 테스트가 정말 실패하는지" 확인하고, 계획서에 없는 불변식(핵심 로직의 가드·분기)도 같은 방식으로 후보에 올린다. 지워도 전 스위트가 녹색이면 기능은 맞아도 **회귀 감지 공백**이므로 심각도를 매겨 보고하고, 그 가드에 도달하는 프로덕션 경로가 있는지까지 밝힌다(도달 가능 = major, 주석이 그 가드를 "이중 안전장치"로 과소평가하고 있으면 함께 지적). mutation은 검증 전용이므로 **바이트 단위 원상복구를 증명**한다(변형 전 md5 및 `git status`/`git diff` 해시와 대조, 잔여 없음 명시).
- **포맷 회귀 판정은 CRLF 노이즈를 제거한 뒤 한다** — 변경 파일을 LF 정규화한 사본에 `gofmt -l`(절차는 CLAUDE.md Windows 항목). CRLF 파일의 `gofmt -d`는 파일 전체를 재작성 형태로 보여줘 실제 위반을 가리므로, "CRLF 함정과 패턴이 일치한다"는 이유로 flag 전체를 기각한 판정은 그 자체가 발견사항이다.
- blocking(재작업 필수)과 제안(non-blocking)을 명확히 나눈다.
- 계획 자체의 결함이면 worker가 아니라 planner로 되돌려야 함을 명시한다.
- 증분 리뷰: 이미 PASS한 항목은 재검증하지 않고 새 변경과 이전 blocking 해소만 본다.
