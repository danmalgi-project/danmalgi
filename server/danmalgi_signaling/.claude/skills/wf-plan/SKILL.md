# wf-plan — 2단계 실행 절차

`planner` 에이전트의 실행 지침. 목표: 확정된 문제 정의 → worker가 판단 없이 실행 가능한 순서화된 계획.

## 절차

1. **입력 확인** — `.claude/workflow/<slug>/01_brainstorm.md`를 읽는다. 미해결 질문이 남아 있으면 계획 확정 전에 오케스트레이터에 확인 요청.
2. **작업 분해** — 가장 작은 안전한 단위로 쪼갠다. 각 단위 종료 시 빌드·테스트가 통과하도록 순서를 잡는다.
3. **영향 분석** — 각 작업이 건드리는 파일/모듈과 계층 경계를 명시. fx 배선(`module.go`) 필요 여부를 반드시 표시한다.
4. **proto 영향 판정** — 계약 변경이 있으면: submodule 반영 → `/proto-build`(`pkg/gen` 재생성) → handler/mapper/usecase 갱신 순서를 계획에 포함한다.
5. **테스트 계획** — 작업별로 추가·수정·제거할 테스트와 실행 명령을 적는다 (CLAUDE.md 테스트 유지 지침).
6. **리스크 & 롤백** — 위험 지점과 되돌림 방법 표시.

## 산출물 형식 (`02_plan.md`)

```markdown
# 2단계: 구현 계획 — <제목>

## 목표            (한 줄)
## 작업 분해        (순서화; 각 작업: 대상 파일/모듈 · 변경 내용 · 완료 조건)
## proto 영향       (변경 여부 / 재생성 절차 / 다운스트림)
## 테스트 계획      (추가·수정·제거할 테스트 + 실행 명령)
## 리스크 & 롤백
```

## 원칙

- worker의 판단 여지를 최소화한다 — "어디를, 무엇으로, 왜".
- **부작용을 겸하는 루프에 skip/continue를 넣도록 지시하기 전에, 그 루프가 수행하는 다른 부작용을 먼저 확인한다.** 순회 상단에서 대상을 통째로 skip하면 그 순회에만 걸려 있던 다른 부작용(리소스 첨부·등록·상태 갱신 등)까지 함께 사라져 회귀가 된다. skip의 **적용 단위(바깥 루프 vs 안쪽 루프)** 를 근거와 함께 지정하라 — "무엇을 거르는가"뿐 아니라 "어느 층위에서 거르는가"까지가 계획의 몫이다.
- 테스트를 작업과 함께 계획한다 (사후에 붙이지 않는다).
- **커버리지 자기검증 목록은 "이 상태를 만드는 다른 경로"를 열거해서 만든다.** 위 skip 원칙의 읽기 경로 버전이다 — 어떤 가드가 방어하는 상태를, **정상 경로가 아닌 부수 경로**(생성 부작용이 있는 읽기/teardown 헬퍼, 콜백, 재시도 등)로도 만들 수 있는지 따져보고 만들 수 있으면 그 상태를 커버리지 항목으로 **승격**한다. 정상 경로만 열거하면 "그 가드를 지워도 전 스위트가 녹색"인 공백이 남고, worker가 계획을 정확히 이행했는데도 load-bearing 가드가 무방비로 남는다(계획 결함이므로 worker 책임으로 돌릴 수 없다).
- 이 단계에서는 **코드를 수정하지 않는다.**
